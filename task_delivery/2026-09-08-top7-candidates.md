# 2026-09-08 GitHub 高热度 AI Skill / Agent：7 个真实评测候选

## 本轮结论

本轮按同一套 GitHub 检索配置抓到 162 个去重仓库，其中 129 个通过“许可证明确、非归档、非禁用、非 Fork、近期仍维护”的机器硬门。再与当前选题库和挖掘历史做语义去重，保留下面 7 个适合进入本地安装与真实任务评测的候选。

这里的“高热度”只表示 GitHub 当前快照和内容题材潜力；今天只有一个时点快照，不能声称增长速度，也不能把 Star 写成质量、实测结论或未来流量保证。

## 逐项评测设计（以下编号沿用最初发现顺序，不代表当前优先级）

## 01｜SkillSpector：安装 Skill 之前，先看它会不会偷数据

- 固定提交：`704bc9544260c2f41222dc0f92982521709496ab`
- 许可证：Apache-2.0；冻结时最新 Release：`v2.11.1`
- 普通人任务：准备一个只含合成样例的 Skill 文件夹，其中放入安全规则、可疑提示词注入和模拟外发代码；不接真实密钥。
- 真实交付：终端、JSON 和 Markdown 风险报告；人工逐项判断哪些是命中、误报和需要阻断安装的项目。
- 5—10 秒证明：左侧是待安装 Skill，右侧立即出现风险类别、具体文件与行号；删除风险样例后再扫，只在公开承诺复扫时执行第二次。
- 内容入口：`这个高 Star Skill 能不能装？我先让另一个 AI 把它扫一遍`
- 主张边界：作者关于漏洞比例、恶意比例和验证管线的数字只能写成作者/官方说明；我方必须用自己的合成夹具和扫描结果形成结论。
- 实跑优先级：最高。官方提供 `--no-llm` 和 Docker 路线，可在无密钥隔离环境先完成最小验证。

## 02｜Humanizer：同一篇 AI 稿，能不能改得像人写又不改事实

- 固定提交：`9862685f575c65a8247f90369951df1b3416e3d6`
- 许可证：MIT；冻结时最新 Release：`v3.0.0`
- 普通人任务：用一篇 800—1,000 字的原创中文产品说明作为冻结输入，数字、专名和事实不可变化。
- 真实交付：改写稿、逐项差异、事实保持检查和一次盲读人工判断。
- 5—10 秒证明：同屏显示原稿套路句与改后句，随后把数字和专名核对结果放到同一画面。
- 内容入口：`AI 稿一眼就被看出来？我只加一个 Skill，再让人盲读`
- 主张边界：风格自然度是人工判断，不用关键词数量冒充“更像真人”；英文规则是否适合中文必须通过本次中文输入验证。
- 实跑优先级：高。安装轻，但结果审阅必须独立于 Skill 自己的说明。

## 03｜Diagram Design：复杂方案，不再自动长成一堆灰色方框

- 固定提交：`2724fd2efd8c6737f6fa704fbf5da52d67375497`
- 许可证：MIT；冻结时没有 GitHub Release，必须按该提交安装。
- 普通人任务：把同一份 600 字原创流程说明变成一张手机可读的自包含 HTML/SVG 图解。
- 真实交付：可打开的 HTML、SVG、信息层级说明和手机缩图验收。
- 5—10 秒证明：先给普通流程图，再切到同信息量的编辑式图解，放大一个关键关系证明不是只换颜色。
- 内容入口：`流程图为什么总像后台？这个 Skill 先替你选对图解类型`
- 主张边界：仓库 README 当前写 39 类图解；冻结快照描述仍写 38 类，公开数量必须以固定提交内实际目录复核为准。
- 实跑优先级：高。结果强可视，但无 Release，需要提交级安装和来源固定。

## 04｜Book to Skill：一本技术资料，变成工作时能直接调用的 Skill

- 固定提交：`a6cad12dee07a7700068e2aa51cba871ef3b5349`
- 许可证：MIT；冻结时最新 Release：`v1.4.0`
- 普通人任务：使用我们原创或明确开放许可的小型技术手册，生成一个可检索、可回答具体工作问题的 Skill。
- 真实交付：生成的 Skill 目录、索引、一个事实问答结果、引用定位和版权检查。
- 5—10 秒证明：把一个具体问题交给新 Skill，画面直接跳到对应章节依据，再展示生成目录。
- 内容入口：`这本 PDF 不再每次重读：我把它做成了一个能工作的 Skill`
- 主张边界：仓库声称的 Token 降幅和“不幻觉”不能当我方结论；本轮只测自己的资料、问题、引用准确性和输出是否过度复制原文。
- 实跑优先级：中高。价值强，但要先锁定资料权利和 PDF 提取依赖。

## 05｜Open Code Review：代码改完别靠感觉，先看它能抓住哪一行

- 固定提交：`04284b5dc19e0f52528ca466a767e4a2c100e5f5`
- 许可证：Apache-2.0；冻结时最新 Release：`v1.11.6`
- 普通人任务：对一份我们原创的微型仓库做审查，其中预先植入空值、输入处理和并发边界三类已知问题。
- 真实交付：JSON 行级审查结果、已知问题命中表、误报/漏报和人工采用判断。
- 5—10 秒证明：代码中一个已知缺陷与审查意见同屏；随后显示它是否准确落到对应行。
- 内容入口：`我故意埋了 3 个 Bug，这个代码审查 Agent 到底能抓几个`
- 主张边界：作者 Benchmark 的精度、F1、Token 和速度属于作者测试；我方只报告冻结夹具上的命中、漏报、噪音和模型条件。
- 实跑优先级：中。可使用当前 Codex 委派模式，但必须冻结模型、输入代码和规则。

## 06｜SkillOpt：一个总失败的 Skill，能不能从失败记录里把自己改好

- 固定提交：`79124b37e9a6371e13b753f8bcd7adb1e493ade1`
- 许可证：MIT；冻结时最新 Release：`v0.2.0`
- 普通人任务：给一个刻意写得不完整的原创分类 Skill，准备训练样例与独立保留样例；限制优化轮次和模型成本。
- 真实交付：基线 Skill、优化后的 `best_skill`、训练轨迹、保留样例结果和人工判断。
- 5—10 秒证明：同一个保留样例在优化前失败、优化后通过；训练样例与保留样例明确分开。
- 内容入口：`Skill 写坏了不用手改？我把失败记录交给它自己重写`
- 主张边界：不能用训练样例上的变好冒充泛化；作者论文、博客和 Benchmark 结果不等于我方实测。
- 实跑优先级：中低。需要先核定模型、运行时长和调用成本，超出预算则 HOLD。

## 07｜Distilly：把一个人的经验，交接成 Agent 能调用的思考档案

- 固定提交：`cf15171f37fcfc4ab7638210705a2973f2b8186a`
- 许可证：MIT；冻结时没有 GitHub Release，README 明确标注开发预览。
- 普通人任务：只用一组获授权的原创访谈笔记和公开文章，生成一个人物思考档案，再回答一项新的工作决策。
- 真实交付：来源清单、人物档案、同问题使用前/后的回答、归属边界和人工判断。
- 5—10 秒证明：同一个新问题先给普通回答，再让人物档案介入，标出哪条来源改变了判断。
- 内容入口：`老员工走了，经验也会走？我把他的判断方法做成 Agent 档案`
- 主张边界：不能冒充真人、不能写成“复制了一个人”；私密资料、邮件和未授权人物材料不得进入本轮。
- 实跑优先级：最后。需要 Node 22.19+、pnpm、Codex 重启，且当前是未发布的开发预览。

## 为什么没选 Star 更高的项目
