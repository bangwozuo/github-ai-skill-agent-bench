# GitHub AI Skill / Agent 爆款评测工作流

## 双证据链

```text
市场热度链
检索式 → 时点快照 → 跨期增量 → 普通用户需求 → 内容库去重
→ 双账号路由 → 爆款逻辑初筛 → 有界可行性 → 值得复现候选

真实适用链
官方仓库 → 许可证 → 固定提交 → 隔离安全预检 → 官方步骤安装
→ 冻结输入 → 原始日志 → 实际结果 → 人工判断 → 窄结论

两条链同时成立
→ 证据化评测报告
  ├─ 只读交接回执 → 现有FLOW文本、审批与生产
  └─ 单作品公版包 → 精确GitHub目标确认后发布 → 发布后学习
```

Star、Fork、README、作者 Demo 只能进入市场热度或来源身份，不能替代本地复现。一次本机结果也不能反推市场热度或保证传播。

## 阶段与交接物

| 阶段 | 消费输入 | 必须产出 | 放行条件 | 失败去向 |
|---|---|---|---|---|
| 1. 发现 | 版本化检索式 | `discovery-YYYYMMDD.json` | 查询、时间、API版本和原始指标齐全 | 修查询或等待限流 |
| 2. 趋势 | 两个同口径快照 | `momentum.json` | 观察顺序正确、公共仓库身份相同 | 只保留时点热度 |
| 3. 初筛 | 快照、趋势、许可证、更新状态 | `shortlist.json` | 无归档/分叉/许可证硬阻塞 | 市场观察，不安装 |
| 4. 账号/爆款/可行性 | 候选、真实重复任务、两个账号规则、内容库与既有成片 | `candidate-review.json`、`editorial-receipt.json` | 受众与调性、账号原生链、点击承诺、5秒证明、拿走物、复杂度、成本和停止条件齐全 | HOLD或带条件实跑 |
| 5. 身份冻结 | 官方仓库 | `candidate.json` | 官方URL、许可证、README、40位提交SHA齐全 | HOLD |
| 6. 隔离复现 | 候选、基准题 | `EVALUATION-RUN.json`、运行卡 | 临时容器/虚拟机、无密钥、最小权限 | 人工安全复核 |
| 7. 安装实跑 | 官方步骤、冻结输入 | 环境、安装日志、运行日志、结果 | 同一提交、同一输入、日志未剪裁 | 记录失败，不美化 |
| 8. 人工采用 | 实际结果 | `adopt / trial / reject` | 可用性、代价、边界已判断 | 返到所属阶段一次修复 |
| 9. 证据验证 | 全部哈希绑定物 | `EVALUATION-RECEIPT.json` | 所有硬项通过 | HOLD |
| 10. 报告与内容 | 验证回执 | 评测报告、内容候选 | 窄结论与证据强度一致 | 降级主张 |
| 11. 双出口 | 通过的评测回执 | FLOW只读交接、公版仓库包 | 不改现有状态；公版无第三方源码/私密材料 | 分支独立HOLD |

## 运行原则

- 默认只跑一个代表性真实任务；只有公开承诺“换一份材料也能跑”时才增加变化输入。
- 安装失败也是有效结果，但只能称“本次按官方步骤在某环境失败到某一步”。
- 不打可抵消硬伤的总分。许可证未知、输入错版、日志缺失、结果不可用，任一项都直接 HOLD。
- 热度阈值只是研究队列控制；“高潜候选”必须等待真实发布数据，不能在内部验证后升级为“爆款”。
- `validate-editorial` 的通过只表示候选级账号、爆款初筛和实跑字段完整；正式三角色文本评审、录制评审和成片评审仍消费各自的真实资产。
- 远程发布必须有精确GitHub目标和当前授权；缺少时停在本地 `draft_ready`，不影响现有FLOW分支继续。

## 双成果

- `workflow_asset/`：检索配置、基准题、质量门、候选审阅模板、只读桥接配置、流程图。
- `task_delivery/`：引擎设计说明，以及每个真实候选生成的评测报告、结论、建议与单作品GitHub公版包。
