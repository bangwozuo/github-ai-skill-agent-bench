# 隔离安装与真实复现手册

## 为什么不直接在工作主机安装

GitHub 仓库、依赖包和安装脚本都属于不受信任代码。评测时需要的是“能否在明确环境跑出结果”，不是让候选项目获得个人文件、浏览器凭证、SSH 密钥或宿主机权限。

## 推荐隔离层级

1. 一次性虚拟机：适合需要桌面、浏览器或系统服务的 Agent。
2. 无密钥容器：适合 CLI、Python/Node 项目；构建期可按需联网，运行期默认 `network=none`。
3. Windows Sandbox：适合 Windows 专用客户端或安装器；关闭后清空。
4. 仅当官方明确要求且风险已人工接受时，才在专用测试机运行；不在日常主机直装。

## 最小权限

- 不挂载用户目录、浏览器配置、SSH、云盘和真实项目仓库；
- 只给一个合成输入目录和一个空输出目录；
- 不传入 Token、Cookie、API Key；确需密钥的候选先停在 `blocked`；
- 禁止管理员/特权容器、宿主 Docker Socket 和未声明的外发；
- 对 CPU、内存、磁盘、运行时间和网络设上限；
- 不自动执行仓库中的 Git Hooks、发布脚本或云端部署。

## 日志纪律

完整保留官方步骤、偏差、标准输出、错误输出、退出状态、耗时和实际结果。媒体使用脱敏副本；原始日志不为“看起来成功”而剪裁。修复必须另开一次有编号的运行，不能覆盖失败记录。

## 可视证明

`actual_result` 只需要同一次运行的输入、日志和结果；`native_run` 还需要真实可视过程与独立 QA。静态成功页、重做 UI、README GIF 和作者 Demo 都不能替代本次原生过程。
